## Overview

The application uses:
- **Frontend**: Vite + React static single-page application.
- **Backend API**: Vercel Serverless Function at `/api/checklist.ts`.
- **Database**: Vercel KV (Redis REST API) for persisting checklist states and timestamps.

When Vercel KV is linked, Vercel automatically sets secret environment variables for the Serverless Function.

---

## Environment Variables Reference

| Environment Variable Name | Purpose | Required Where | Auto-Generated by Vercel KV? |
|---|---|---|---|
| `KV_REST_API_URL` | REST endpoint URL for your KV database | Local `.env.local` & Vercel | **Yes** (when database is linked) |
| `KV_REST_API_TOKEN` | Bearer token for authenticating KV REST requests | Local `.env.local` & Vercel | **Yes** (when database is linked) |
| `KV_REST_API_READ_ONLY_TOKEN` | Read-only token (optional) | Local `.env.local` & Vercel | **Yes** (when database is linked) |
| `KV_URL` | Redis connection URL | Local `.env.local` & Vercel | **Yes** (when database is linked) |

> ⚠️ **Important Security Note**: These variables are **server-side secrets** used by `/api/checklist.ts`. They should **never** be prefixed with `VITE_` or exposed to client-side code.

## Local Development Setup (`.env.local`)

If you want local development (`pnpm dev`) to read/write from your actual Vercel KV database:

1. Create a `.env.local` file in the root of the project:
   ```bash
   cp .env.example .env.local  # or create .env.local manually
   ```

2. Add your Vercel KV REST API credentials (copied from the Vercel Dashboard):
   ```env
   KV_REST_API_URL="https://your-kv-db.upstash.io"
   KV_REST_API_TOKEN="AXXX...XXX="
   KV_REST_API_READ_ONLY_TOKEN="AYYY...YYY="
   KV_URL="redis://default:token@your-kv-db.upstash.io:6379"
   ```

> 💡 **Note**: If `.env.local` is missing or variables are empty, the app runs gracefully using `localStorage` caching without breaking.

## Step-by-Step Vercel Deployment

### Step 1: Push Project to GitHub
Ensure all latest changes are committed and pushed to your GitHub repository:
```bash
git add .
git commit -m "Add Vercel KV persistent storage integration"
git push origin main
```

---

### Step 2: Import Project into Vercel

1. Log into your [Vercel Dashboard](https://vercel.com/dashboard).
2. Click **Add New...** → **Project**.
3. Select your GitHub repository (`MissionAppRequirementsChecklistReactApp` or similar).
4. Configure Project Settings:
   - **Framework Preset**: `Vite`
   - **Root Directory**: `./` (default)
   - **Build Command**: `pnpm build` (or `npm run build`)
   - **Output Directory**: `dist`
   - **Install Command**: `pnpm install`
5. Click **Deploy**.

---

### Step 3: Create & Link Upstash Redis (Vercel KV) Database

Vercel recently migrated first-party Vercel KV to the **Upstash Redis** integration.

1. In the Vercel Storage modal (shown in your screenshot), select **Upstash** (or **Redis** under Marketplace Database Providers).
2. Click **Continue**.
3. Log in or authorize Upstash (free tier with 10,000 requests/day).
4. Click **Create Database**:
   - Name: `mission-app-kv` (or any name)
   - Primary Region: Choose the region closest to your users.
5. Click **Connect to Project** and select your project (`mission-app-requirements-checklist`).
6. Select environments: **Production**, **Preview**, and **Development**.
7. Click **Connect**.

> 🎉 **Vercel will automatically inject `KV_REST_API_URL` / `UPSTASH_REDIS_REST_URL` and `KV_REST_API_TOKEN` / `UPSTASH_REDIS_REST_TOKEN` into your project's Environment Variables!**

---

### Step 4: Verify Environment Variables

1. Go to your project settings: **Settings** → **Environment Variables**.
2. Confirm the following system variables exist:
   - `KV_REST_API_URL`
   - `KV_REST_API_TOKEN`
3. If you want to copy these keys for local development (`.env.local`):
   - Click **Copy Snippet** or expand the secret to copy its value into your local `.env.local`.

---

### Step 5: Redeploy Application

After linking the KV database, trigger a new deployment so the Serverless Function `/api/checklist.ts` picks up the newly added environment variables:

1. In Vercel, go to the **Deployments** tab.
2. Click the three dots (`...`) next to the latest deployment → **Redeploy**.
3. Click **Redeploy** to confirm.

---

## Verification & Testing

Once redeployed:

1. Open `https://mission-app-requirements-checklist.vercel.app/` in **Browser A** (or Laptop).
2. Check an item (e.g., `RF 1.1 Login`).
3. Open `https://mission-app-requirements-checklist.vercel.app/` in **Browser B / Mobile Device**.
4. Verify that `RF 1.1 Login` is already checked on Browser B when the page finishes loading.
5. Uncheck an item on Browser B, reload Browser A, and verify the update reflected.

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| Changes only persist locally on one browser | Vercel KV not linked or env variables missing | Go to Vercel Storage → Link database to project → Redeploy |
| `500 Internal Server Error` on `/api/checklist` | Missing/invalid `KV_REST_API_TOKEN` | Re-link KV storage in Vercel settings and redeploy |
| API function returns `{"warning": "Vercel KV not configured"}` | Serverless Function running without env variables | Verify environment variables exist under **Settings → Environment Variables** |
